After many years and much development, the kpt community has released v1.0.0 of the kpt toolchain. This is a big step in maturing the kpt project after having it in pre-release status for several years. In the last twelve months the community has focused on stabilising the APIs, deprecating unused features and integrating the Porch (Package ORCHestration) service back into the kpt organization. With the complete toolchain under a common governance the community delivers a comprehensive system for GitOps based package management, which is modular enough to integrate and add value to any workflow.

Standalone kpt provides lightweight configuration package management for applications running on Kubernetes, based on the config as data principles. These principles allow declarative manipulation and verification of the configuration of cloud native applications, clusters or indeed any resources managed through Kubernetes APIs. In kpt everything is expressed using KRM and kpt provides a framework to describe the manipulation and validation steps for KRM resources in a package, autonomously converting generic KRM into deployable models for a specific site or application. This allows reproducible KRM resource manipulation without the limitations of templating. Porch provides a framework to support the orchestration of kpt packages at scale in a zero-touch GitOps workflow.

With the recent release of version 1.0.0, the kpt community is announcing the readiness of kpt for widespread adoption, having demonstrated that all the components of the project are stable and the community is actively working to build a simple, comprehensive, lightweight and modular framework for the lifecycle management of any Kubernetes resources.
