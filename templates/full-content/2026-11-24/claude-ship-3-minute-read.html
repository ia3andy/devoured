Claude Ship is a set of agents that help get your team’s GitHub pull requests ready to merge:

  • Code Review: looks for issues such as logic errors, security vulnerabilities, and broken edge cases
  • PR Steward: works on review feedback and failing checks
  • Claude Approvals: checks pull requests against an approval policy that you write

Together, they can take a pull request through review, fixes, and an approval decision, so your team doesn’t have to manage each step manually. Your settings and GitHub branch rules determine what merges. Claude Ship is available on Team and Enterprise plans. To turn on the agents, go to Set up Claude Ship. To get a review and fixes locally, on one of your own pull requests, run /ship in Claude Code.

Claude Ship agents

Claude Ship uses AI and may miss bugs, security vulnerabilities, or other issues.

Code Review finds problems

Code Review reads a change alongside the surrounding code. Findings arrive as inline comments on the lines concerned, ranked by severity.

PR Steward pushes fixes

PR Steward works on failing checks, merge conflicts, and review comments from people and from review bots such as Code Review. It pushes commits with its fixes. Steward is designed not to approve or merge pull requests. Use branch protection to require the approvals you want before anything merges.

Claude Approvals applies your policy

Claude Approvals is a check that reports who still has to approve. You write its policy file, which can set how many people have to approve changes to a path, and where Claude can post an approving review. The check blocks a merge only where you make it a required check in GitHub, and normally not in observe mode. If you use GitHub auto-merge or a merge queue with a policy that doesn’t require a person’s approval, a change can merge without anyone acting.

Set up Claude Ship

Go to Organization settings > Claude Ship for Claude Ship’s settings. You need an Owner role. Turn on one agent at a time in one repository, in this order:

  1. Set up Code Review
  2. Set up PR Steward. For the setting that chooses when PR Steward starts, begin with Manual (@claude steward). PR Steward has no spend limit of its own until you set one.
  3. Set up Claude Approvals. A policy file in the repository starts it, so see who can turn it on. Start in observe mode, where the Claude Approvals check reports what your policy would decide. Observe mode is billed.

If you already use Code Review

Code Review’s settings moved to Organization settings > Claude Ship. A Claude Approvals policy file, .claude/approvals.yml, changes which pull requests Code Review reviews automatically. Once the file is on the default branch, in observe mode or enforced, automatic reviews normally stop where no matching rule names claude/code_review. To keep them, add claude/code_review to a rule.

Plans and billing

Claude Ship is for organizations on Team and Enterprise plans.

Who can use Claude Ship

Code Review is generally available. PR Steward and Claude Approvals are in public beta. The agents aren’t available to organizations with Zero Data Retention enabled, the HIPAA configuration applied, or customer-managed encryption keys.

How each Claude Ship agent is billed

Each agent is billed on token usage through your organization’s usage credits, separately from your plan’s included usage. Approvals bills for classifier runs and the Code Reviews that a policy asks for. Eligible Enterprise organizations can claim promotional Claude Ship credits. If you turn off usage credits in Organization settings > Usage, an agent that’s on keeps running and billing your organization. To stop its charges, follow Turn off Claude Ship.

Turn off Claude Ship

Turn off Approvals before Code Review, because a policy can start billed reviews where Code Review is off:

  1. Turn off Approvals
  2. Turn off PR Steward
  3. Turn off Code Review

These steps leave the /ship and /steward commands on.
