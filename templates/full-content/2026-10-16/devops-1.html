Spacelift Announced as the First Infrastructure Automation Platform to Integrate with Cursor Origin

Your engineers already push half their code through an AI agent before a human ever looks at it. That’s fine when the change is a function signature. It’s a different conversation when the agent is proposing a change to the load balancer sitting in front of production, or more importantly, your IAM policy. Someone still has to answer for what gets applied, and right now that someone is you.

The fix isn’t reviewing faster. It’s putting guardrails inside the workflow where agents actually propose changes, so a policy check and an approval step stand between any pull request and production, no matter who or what opened it. Spacelift already works this way for GitHub, GitLab, and Bitbucket. The next place that needs to happen is wherever AI agents do their work.

This is where Cursor Origin fits in. Origin is Cursor’s new version control platform for teams building with AI agents. Spacelift is proud to be the first infrastructure orchestration platform to integrate with Origin as a launch partner.

Meet the repo built for AI agents

Origin is Cursor’s alternative to GitHub: a place to host repositories, open and review pull requests, and keep code, pull requests, and AI agents in the same interface. It can mirror existing GitHub repositories at the click of a button, so teams don’t have to migrate everything manually on day one. This makes migration easy, or allows teams to use both so they can continue working even when providers are having issues.

Same guardrails, new source

Spacelift already runs on top of GitHub, GitLab, and Bitbucket. Policies trigger on push, plans run before anyone applies anything, and every deployment carries the guardrails you set up around it. The Origin integration extends that same model to infrastructure changes that start life inside Cursor.

Spacelift connects to Origin as a registered app authenticated with its own signing key rather than a person’s credentials. The app is scoped to source code and API access, not authentication, and it shows up right where a GitHub App would: in Origin’s settings and on the pull request view. The integration is available across all of Spacelift’s regions.

Whether a deployment change originates from an AI agent or a human operator, Spacelift enforces the exact same governance rules. Your OPA policies and your approval flow apply the same way to a change opened in Origin as one opened anywhere else. The agent can write the plan, but doesn’t get to skip the review.

Origin gets the same trigger model Spacelift already uses for GitHub: a push updates a tracked run, and opening a pull request kicks off a proposed run, etc. Every framework Spacelift supports today, Terraform (including Terragrunt), OpenTofu, Pulumi, CloudFormation, Ansible, and Kubernetes, works the same way through Origin. Nothing changes about what you can run. The only thing that changes is the VCS where it is run from.

The agent doesn't get to skip review

AI agents are already writing production infrastructure changes faster than most platform teams can review them manually.

In Spacelift’s 2026 Infrastructure Automation Report, 76% of infrastructure teams say they would apply AI-generated Terraform and HCL to production with little or no review, and 93% have already had at least one AI-caused infrastructure incident. Tools like Origin put those agents directly inside the pull request flow developers already trust. Letting agent-generated changes slip through a review process built for a slower era is exactly how teams get hurt, and among early adopters of agentic AI, the incident rate is already running at 33%.

Being first here means Spacelift customers don’t have to choose between adopting AI-assisted development and keeping production guardrails in place: The same plan, policy check, and approval step that stands between a person’s pull request and your infrastructure now stands between an agent’s pull request and your infrastructure from day one, rather than after the first incident forces the question.

“We built the governance model for Spacelift to travel with the pull request, not the platform it lives on. Origin was a natural extension: the same policies, the same approval flow, the same audit trail, now supported by an agentic first source rather than a human one as our software development undergoes a similar shift,” said Spacelift SVP Product and Design, Jonah Kowall

Enable governance for Origin

Connect Origin from Integrations in your Spacelift account, the same place you’d connect GitHub, GitLab, or Bitbucket. Every pull request Origin opens gets the same plan, policy check, and approval step your other repositories already have.
