No custom integration work required. You stay in the editor, ask in plain language, and the context comes to you. Deployment health analysis with Claude Code

Every deployment carries risk. Even well-tested releases can introduce regressions that only show up under real production load. There’s now a faster way to answer the question: "Did this deployment break anything?”

With New Relic MCP Server connected to Claude Code, a developer can ask a single question right from their terminal:

"How did my last deployment perform?"

New Relic MCP Server pulls together a comprehensive picture from across our Intelligent Observability Platform—metrics, logs, traces, error rates, alert history, and more—and returns a full deployment health report. If something went wrong, Claude Code not only tells you what broke; it also has enough context to start working on a fix right in the same session.

Using Claude Code? Install the New Relic Claude plugin
Our New Relic Claude plugin is now live on the Anthropic marketplace. You can install it directly from the marketplace or access our source on GitHub and install it using the command below:

claude plugin install newrelic@claude-plugins-official

Infrastructure optimization with Kiro

Managing Infrastructure as Code (IaC) involves an annoying disconnect: You write Terraform or CloudFormation in your editor, but the performance data proving whether you over-provisioned or under-resourced lives in a separate dashboard.

To close this gap, we launched a New Relic Kiro Power. This transforms Kiro into an infrastructure engine driven by real production data. It pulls live telemetry—like CPU bottlenecks and memory spikes—straight from New Relic into your Integrated Development Environment (IDE). If a service is struggling under peak load, Kiro doesn't just show you the metric; it also analyzes the New Relic data and instantly generates the exact IaC code changes needed to right-size your environment. New Relic provides the production ground truth, and your IDE writes the fix.

Closing observability gaps with GitHub Copilot

One of the most common problems teams face when shipping new services is incomplete observability coverage. You deploy something and realize weeks later that you have no application performance monitoring (APM), no browser monitoring, and/or no change tracking. Finding and fixing those gaps manually is tedious and easy to deprioritize.

Our New Relic MCP Server integration with GitHub Copilot enables developers to identify observability gaps, understand production behavior, and accelerate remediation without leaving their coding environment.

How it works:

  1. A GitHub Action tracks code releases for a repository and triggers an observability gap analysis
  2. GitHub Copilot chat connects to the New Relic MCP Server, which in turn communicates securely with GitHub's MCP Server through an associated GitHub App
  3. The analysis runs and surfaces specific gaps
    1. For example: Missing APM, browser monitoring, or change tracking
  4. GitHub Issues are automatically created for each gap, complete with an implementation checklist, detailed instructions, and deep links to relevant New Relic documentation
  5. GitHub Copilot coding agent is assigned to each issue and gets to work, analyzing the requirements, implementing the necessary code changes, and opening a pull request

The power is in the full loop: New Relic detects the gap, GitHub Copilot fixes it, and the PR contains everything needed to close that gap—tested, documented, and ready for review. Future checks will extend to infrastructure monitoring, synthetics, logging, and alerts.

Orchestrating automated observability with GitHub custom agents

Finding the critical information with GitHub custom agents and MCP Servers takes knowledge and time to engineer prompts that make it easy for the AI agent to use the right tools and format a meaningful response. Using a custom agent from GitHub finely tuned to New Relic MCP Server allows for simpler one-line inputs that generate robust responses.

Take the example of the incident response custom agent: You can check in on an incident within your organization by running a simple prompt like this:

“Check on the latest incident for this application”

The custom agent can then create a full report and kick off a multi-step process to analyze any major incidents and break down what has impacted any critical data with the incident.
