Pick the right skill for the job.

Thirteen skills, one install. Each one is a single SKILL.md your agent reads before it touches the UI.

  • taste-skill: Default, v2. Reads the brief, infers the right design direction and ships interfaces that do not look templated. Real design systems when they fit, audit-first on redesigns, and a strict pre-flight check.
  • taste-skill-v1: The original v1, preserved for projects that depend on its exact behavior. Use it only if v2 breaks something specific.
  • gpt-tasteskill: A stricter variant tuned for GPT and Codex models, with stronger layout variance and motion direction.
  • redesign-skill: For existing projects that need a proper visual audit and a cleaner redesign pass.
  • image-to-code-skill: Generates design references first, studies them closely, then implements the frontend to match.
  • output-skill: Keeps output complete. No placeholders, skipped sections or half-finished work.
  • soft-skill: Calm, expensive-looking interfaces with softer contrast, generous whitespace and smooth motion.
  • minimalist-skill: Editorial product UI with restrained color, sharp structure and a tighter hierarchy.
  • brutalist-skill: A harder, mechanical language: Swiss typography, raw structure and sharper contrast.
  • stitch-skill: Google Stitch compatible design rules, with an extra DESIGN.md export format.
  • imagegen-frontend-web: Website reference images with strong art direction, typography and spacing discipline.
  • imagegen-frontend-mobile: Mobile screen concepts and flows with clean hierarchy and consistency across screens.
  • brandkit: Brand kit boards with logo concepts, color systems, typography and mockups.

What's new in v2.

A 2026 rewrite of the default skill. The agent reads the brief, infers the right direction and ships interfaces that do not look templated. Same install, a much stricter ruleset.

$ npx skills add Leonxlnx/taste-skill --skill design-taste-frontend

v2 is experimental and already the default. The install name stays stable while rule wording settles before 2.0. Pinned to v1? Use design-taste-frontend-v1.

  • Brief inference: The agent reads the room before generating: industry, audience, mood, motion depth and layout family.
  • Brief to design system map: When to reach for Material, Fluent, Carbon, Polaris, Primer, Radix, shadcn or Tailwind, and when native CSS is the better call.
  • Dark mode protocol: Dual-mode by default, with contrast and hierarchy parity across themes.
  • Redesign protocol: Audit-first on existing projects, with preservation rules and explicit modernisation levers.
  • Block library schema: A contract for adding blocks over time so the library stays coherent.
  • Hard pre-flight check: Every box has to honestly pass before the agent ships output.

How Design Mode works

  1. Brief: Reads your request, fills the gaps and writes down its assumptions.
  2. Direction: Makes explicit brand, copy, layout, asset and motion decisions.
  3. Build: Your chosen agent implements them in your real project.
  4. Review: Opens the live site, captures real viewports and fixes what is off.
