New Docker. New whale. New mission. 🐳

On November 19, 2026, Docker introduced its new brand identity, including a redesigned logo, a new color palette, and a bigger strategic ambition.

The message? Run on Trust.

As a Docker Captain and container security author, I have a few thoughts. And some book announcements of my own!

1. Docker's Angle: From Containers to Containment

Docker became famous for making applications portable and reproducible. Now, with autonomous AI agents entering development workflows, Docker is positioning itself as the trusted execution layer for both applications and agents.

We need to containerize the application and contain the agent.

What changed?

Old Docker New Docker (2026)

Docker isn't abandoning containers. It's extending the principles that made containers successful into the AI era. Its commitment to containers, open source, and developers continues.

New words, new priorities

Docker's new messaging centers on three pillars:

  1. Trusted Runtime: Isolate and run autonomous agents safely.
  2. Trusted Supply Chain: Protect the software and dependencies those agents use.
  3. Trusted Ecosystem: Bring tools, models, and security controls together.

Two phrases capture the direction particularly well:

Trust Docker for the agents you don't.

Contain your agents, not your ambition.

This is an interesting shift. Containers made software portable. Docker Sandboxes aim to make autonomous execution controllable, with Docker AI Governance alongside them to help teams govern agent activity.

And the whale? He's still here.

Back in October 2013, Docker's community named its whale Moby Dock, a playful reference to Herman Melville's 1851 novel Moby-Dick. Captain Ahab spent that story hunting a whale.

Thirteen years later, Docker's whale has evolved again. Sorry, Captain Ahab. But don't worry: Captain Ahab is still around, too. He's a character in my comic book Black Forest Commandos: Asgard Mission.

On Friday the 13th of November, I released the second edition of Black Forest Shadow, my dark fantasy guide to Docker and Kubernetes security.

The new edition expands from 143 to 194 pages, adds three bonus stories, upgrades the illustrations to full color, and updates the technical lessons with Docker Sandboxes, SIP (Security Immediate Plan), and recent supply-chain attacks.

Even in the Black Forest of 1865, security threats keep evolving.

Docker Sandboxes: Contain, Don't Just Containerize 📦

My next book focuses entirely on Docker Sandboxes (sbx).

I'll cover agent isolation, sandbox architecture, networking, credentials, Kits, reproducible development environments, and the trade-offs between containers and sandboxes.

The fun part? I'm using Docker Sandboxes as the development environment to build the book itself.

Docker and Kubernetes Security 2.0 🐳

Finally, I'm announcing the upcoming second edition of Docker and Kubernetes Security, planned for early 2027.

The first edition covered the security lifecycle from container images to Kubernetes runtime protection. The second edition will revisit that foundation in light of evolving supply-chain attacks, hardened images, attestations, and autonomous development workflows.

It will also feature a redesigned cover aligned with Docker's new identity.

Not merely a new logo on an old book. A proper second edition.
