DBDelve

A fast, native, cross-platform, multi-engine database client. Written in Rust with GPUI, no Electron and no JVM: instant startup, friendly on your memory, and smooth scrolling through large tables where other clients crash or introduce limits.

Why

I wanted something which is performant, modern and consumes little ram. The existing DB clients are either filled with bloat (Electron and JVM) or paid. This is an alternative to them. No feature is ever going behind a paywall and with time we will have complete parity on features with those too.

Install

macOS (Apple Silicon, macOS 12 or later):

brew install --cask ShayanAbbas1/dbdelve/dbdelve

The app isn't notarized, so the cask clears the quarantine flag macOS would otherwise refuse it over. Without Homebrew:

curl -fsSL https://raw.githubusercontent.com/ShayanAbbas1/dbdelve/main/install.sh | sh

Linux (x86_64 or aarch64): the same one-liner installs it under ~/.local with no root, or yay -S dbdelve-bin from the AUR, or the tarball or AppImage from the latest release.

Windows (x86_64): run the installer from the latest release, or unzip the zip and run dbdelve.exe. The installer asks for AppData (just for you) or Program Files (all users).

Supported databases

Postgres, MySQL, MariaDB, SQLite, Turso, DuckDB, Snowflake, SQL Server, MongoDB, Redis (and Valkey, KeyDB, Dragonfly) and ClickHouse.

Any other database with an ODBC driver is reachable through the bundled ODBC bridge, with that driver installed: IBM Db2, Oracle, SAP HANA, SAP ASE (Sybase), Informix, Teradata, Vertica, Exasol, Firebird, Amazon Redshift, Google BigQuery, Databricks, Apache Hive, Trino and Presto, Dremio, InterSystems IRIS, Microsoft Access and more. Grid editing is off, and statements you type run under the connection's mode.

What it does

  • Make it yours. The app's own themes alongside Catppuccin, Tokyo Night, Gruvbox and Dracula, each in dark, light and glass. Import themes from Zed or VS Code, or write your own.
  • Bring your connections with you. Import every saved connection, passwords and SSH settings included, from DBeaver, or TablePlus on macOS.
  • Organize your connections into projects, and jump to any of them from the palette, or disconnect back to a home screen that lists them all.
  • Never mistake prod for staging. Every connection is isolated and can color the title bar. Run it read-only, read-write or with full access, and DBDelve asks before anything destructive.
  • Edits you can read first. Change a cell and DBDelve writes the UPDATE for you to check before it runs.
  • Keep the columns you need. Hide or pin columns, and the layout survives a restart.
  • Read a row in full in the row panel, with JSON highlighted, and edit long values there.
  • Import rows from CSV, TSV or JSON, with every row checked and every statement shown before anything runs.
  • Open a data file by dropping it on the window: a CSV, Excel, Parquet or JSON file opens in DuckDB, held in memory, as a query you can change. A .sql file opens in a new query tab on the connection you're on, and runs only when you run it.
  • See the query plan highlighted in its own pane, with bad row estimates called out.
  • Completion that knows your schema: tables, and a table's columns after its name and a dot. A table is written with an alias, and after JOIN with the condition its foreign keys imply.
  • Keyboard-first. One palette for commands, tables, saved queries, history and connections, and every shortcut rebindable.
  • Your SSH, not a reimplementation. Tunnels run through your own ssh, so your config, agent and hardware keys just work. For Postgres, a Host that is a directory (/var/run/postgresql) reaches that Unix socket on the SSH host, optionally as another user (Run as); the server needs socat, and passwordless sudo for it when Run as is set. TLS modes other than disable and prefer are refused there.
  • Sign in with a short-lived token. On Postgres, MySQL, MariaDB, SQL Server, Redis and ClickHouse, a profile's Password command prints the password at every login, so cloud IAM auth keeps working after the token expires. For Amazon RDS: 
    /opt/homebrew/bin/aws rds generate-db-auth-token --hostname %HOSTNAME% --port %PORT% --username %USERNAME% --region <region>

Free and open source, nothing behind a paywall, and no telemetry: the only request DBDelve makes on its own is an update check, which you can turn off.

Logs and bug reports

DBDelve keeps a diagnostic log on your machine and never sends it anywhere. To attach it to an issue, use Help → Copy Diagnostics and paste; Help → Open Logs Folder shows the files. If the default log doesn't show the problem, turn on Verbose logging in Settings and reproduce it.
